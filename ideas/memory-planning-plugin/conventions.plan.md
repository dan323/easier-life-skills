# memplan — Dual-File Convention & Access Control

## Dual-file convention

Every memory file exists in two forms, kept in sync on every write:

| Extension | Audience | Format | Permissions |
|-----------|----------|--------|-------------|
| `.plan.md` | Human | Prose, headers, tables, readable markdown | **Read-only** (OS-enforced) |
| `.mem` | Agent | MemScript v1 — see `mem-language.plan.md` | Read-only between sessions; agent unlocks to write |

The agent always reads `.mem`. The human reads `.plan.md`. Skills write both on every update.

Files that are already minimal enough for both audiences (single-line, no structure) use no dual:
`progress`, `branch-intent`.

Files that are already machine-structured use no dual:
`deps.json`.

---

## Read-only enforcement for `.plan.md`

`.plan.md` files are generated output — they are derived from `.mem` and have no
independent authority. Direct human edits to `.plan.md` are silently overwritten on
the next agent write.

Enforcement layers (both applied):

**1. OS permissions**
The agent sets `chmod 444` (Unix) or `attrib +R` (Windows) on every `.plan.md`
immediately after writing it. To write, the agent runs:
```
chmod u+w <file>   # unlock
<write>
chmod 444 <file>   # re-lock
```
This blocks accidental saves from editors and scripts without extra tooling.

**2. Generated-file header**
Every `.plan.md` file opens with:
```
<!-- GENERATED by memplan — do not edit directly. Send feedback via .memplan/inbox/ -->
```
This is the first line the human sees. It explains the read-only nature and points
to the correct feedback channel.

---

## Two-channel model

| Direction | Channel | Format | Who writes |
|-----------|---------|--------|------------|
| Agent → Human | `*.plan.md` (read-only) | Readable markdown | Agent only |
| Human/tool → Agent | `.memplan/inbox/*.feedback` | FeedScript v1 | Human, external tools, plugins |

There is no third channel. A human who wants to change the plan writes a `.feedback`
file (or uses a tool that does). The agent processes it on next session start.

---

## Authoritative source

`.mem` is authoritative. `memplan/review` regenerates all `.plan.md` files from
their `.mem` counterparts during hygiene passes. If the two ever diverge (e.g. after
a bug or manual unlock), the `.mem` version wins.
